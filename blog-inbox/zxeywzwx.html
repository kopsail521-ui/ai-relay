Per token, not per request

Claude-class APIs bill on tokens — roughly three-quarters of a word each. Rates are quoted per million tokens, so the per-token price is just that number divided by a million. On KeyoAPI the four Claude lanes cost:

A worked example

Say a support bot sends a 2,000-token prompt and gets a 400-token answer on claude-sonnet-5:

input:  2,000 / 1,000,000 × $0.44  = $0.00088
output:   400 / 1,000,000 × $2.21  = $0.00088
                                     ---------
total per conversation             ≈ $0.0018

Ten thousand such conversations ≈ $18. The same conversation on claude-fable-5 would run ≈ $0.035 — twenty times the cost for flagship quality you may not need on every turn. That ratio, not the headline price, is what per-token budgeting is about: route the routine 90% of traffic to the cheap lane and escalate only the hard cases.

Cutting the bill

  • Escalate, don't default. Run drafts and classification on claude-sonnet-5; promote only failing slices to claude-opus-5 or the Fable lanes.
  • Shift bulk work off Claude entirely. High-volume drafts and classifiers often do fine on gpt-6-luna or deepseek-v4.1-flash on the same key — see OpenAI API pricing page and DeepSeek API pricing page.
  • Prototype for free. Fixed $0 catalog IDs ending in :free bill against your signup gift credit at fair-use limits — draft and smoke-test there, then switch model= to a Claude lane: free models list.
  • Retry around overload, don't re-send. Claude occasionally returns HTTP 529 overloaded; the retry and fallback playbook in our Claude API 529 guide keeps those from double-billing you.
