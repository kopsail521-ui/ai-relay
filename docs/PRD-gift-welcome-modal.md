# PRD — 新用户赠送金欢迎弹窗

## 1. Summary

新用户注册后已自动到账 **$10 赠送金**，但进控制台只能在钱包页才看见，缺少即时说明。本需求在**首次登录进入控制台**时弹出一次欢迎窗，明确：送了多少、只能打免费模型、怎么开始用。

## 2. Contacts

| Name | Role | Comment |
|------|------|---------|
| Owner | 产品决策 | 确认文案与触发时机 |
| Cursor / 工程 | 实现 | SPA 弹窗 + 只弹一次 |

## 3. Background

- 双钱包已上线：注册写 `gift_quota`（默认 $10），公开定价仍标免费/$0。
- 实测：新用户钱包显示「充值 $0 / 赠送 $10」，但注册流程是「创建成功 → 请登录」，登录后无任何提示。
- 为什么现在做：赠送金是获客钩子；看不见 = 不转化为第一次免费调用，也不理解「赠送 ≠ 充值」。

## 4. Objective

**目标：** 注册后第一次进控制台，用户立刻知道「有 $10 赠送金，只能用于免费模型」。

**对公司：** 提高首次免费模型调用率，降低「没额度」误判与客服解释成本。

**Key Results（上线 2 周内，有数据再核）：**
- KR1：首次登录用户中，弹窗曝光后「去试用免费模型」点击率 ≥ 30%
- KR2：注册后 24h 内至少一次 `:free` 调用的比例相对上线前提升（基线待取）
- KR3：因「余额为 0」误报的客服/工单不上升（定性）

## 5. Market Segment(s)

- **主人群：** 刚注册的开发者 / 试用用户（邮箱注册、Google/OAuth、带邀请链接注册均包含）
- **Job：** 立刻搞清「我能免费试什么」并打出第一刀 API
- **约束：** 不把免费讲成要花钱；不暗示赠送金可用于付费模型；弹窗只打扰一次

## 6. Value Proposition(s)

| 用户得到 | 避免的痛 |
|----------|----------|
| 立刻知道有 $10 赠送 | 以为账户是空的、不敢调 API |
| 知道只能打免费模型 | 拿赠送金打付费模型失败后的困惑 |
| 一键去免费目录 / 钱包 | 不知道下一步点哪 |

## 7. Solution

### 7.1 用户流程

```text
注册成功 →（现有）提示去登录
     ↓
首次登录成功，进入控制台任意页
     ↓
满足条件 → 弹出「欢迎礼金」对话框（阻塞式，可关）
     ↓
用户点「去试用免费模型」或「知道了 / 去钱包」
     ↓
本地（+可选服务端）标记已展示，之后不再弹
```

**触发条件（须同时满足）：**
1. 已登录；
2. `gift_quota > 0`（或 ≥ 当前 `GiftQuotaForNewUser` 配置，默认 $10）；
3. 尚未展示过本弹窗（见 7.3 标记）；
4. 建议加：`request_count == 0` 或 `used_quota == 0`（避免老号补弹；仅新号）。

**不触发：**
- 仅注册未登录（当前会跳登录页，无控制台壳）；
- 已点过关闭/主 CTA；
- 管理员手动加赠送的老号（用「零用量」条件挡住，或仅注册后 7 天内账号）。

### 7.2 弹窗内容（文案草案，中英由 i18n）

**标题：** 送你 $10 赠送金  

**正文：**  
欢迎加入 KeyoAPI。账户已到账 **$10 赠送金**，只能用于目录里的**免费模型**（如 `glm-5.3-flash:free`）。公开价仍是 $0；系统按对应付费模型的售价从赠送金扣减。充值余额与赠送金分开，付费模型请先充值。

**按钮：**
1. 主 CTA：**去试用免费模型** → `/free-models` 或控制台 `/pricing` 并筛「免费」
2. 次 CTA：**查看钱包** → `/wallet`
3. 关闭：**知道了**（等同 dismiss）

**视觉：** 沿用现有 Dialog / ConfirmDialog；不要再套一层营销落地页。金额用现网配置换算（`GiftQuotaForNewUser` / `QuotaPerUnit`），文案里写活的美元数，避免写死后改配置不一致。

### 7.3 技术要点

| 项 | 建议 |
|----|------|
| 展示时机 | 登录成功写入 session 后、控制台 layout 挂载时检查 |
| 只弹一次 | `localStorage` 键如 `keyo.giftWelcome.v1.{userId}=1`；有用户设置接口可再加 `setting.gift_welcome_seen` |
| OAuth | 与邮箱注册同一套：首次进控制台即检 |
| 邀请注册 | 被邀请人同样有 $10，同样弹；邀请人侧不弹本窗 |
| 金额源 | 优先读用户 `gift_quota` 展示；副文案可引用 status/options 的 `GiftQuotaForNewUser` |

### 7.4 Assumptions

- 假设用户主要在桌面浏览器完成注册与首次登录。
- 假设「零用量」足以区分新号与被手动加礼的老号；若误伤，改为「注册时间 < 24h」或服务端 `gift_welcome_pending` 标志。
- 假设不在注册成功 toast  alone 解决感知（因强制去登录，toast 易错过）。

## 8. Release

| 范围 | 内容 | 体量 |
|------|------|------|
| **V1（本迭代）** | 首次登录弹窗 + localStorage 只弹一次 + 中英 i18n + 双 CTA | 约 0.5–1 人日 |
| V1.1 | 服务端 `gift_welcome_seen`，换设备也不再弹 | 小 |
| 以后 | 邀请人「好友已注册，你 +$3」轻提示（另需求） | — |

**验收：**
- 新号登录后出现弹窗；金额与钱包赠送金一致。
- 关闭后再进控制台不再出现。
- 文案不出现「上游」；不暗示赠送金可打付费模型。
- 老号（已有用量）不弹。

**非目标：** 改注册直登、改扣费逻辑、改公开定价文案。
