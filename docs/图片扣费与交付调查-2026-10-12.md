# 图片扣费与结果交付调查

日期：2026-10-12。内部技术记录，不用于公开模型文案。当前调查没有修改生产余额、创建诊断令牌、发起付费生成或部署。

## 用户反馈与能确认的事实

用户先反馈本地图片没有原始 URL，调用 `/v1/uploads` 和 `/v1/files` 均收到 503，因而未继续发起付费生成。随后反馈有两条图片费用，并补充可能是已经生成成功但没有收到图。这些反馈可能来自不同请求，不能仅凭模型名将它们合并成同一交易。

账单截图通过本机 OCR 检查，可靠辨认的模型为 `nano-banana-pro`、`gpt-image-2-vip`，记录内容包含 `image precharge model=...`，耗时显示 0.0s。截图没有可关联的 request ID、task ID、user ID 或 token ID。金额 OCR 不可靠，不能据此确认实际金额。

使用已有管理令牌只读 GET 管理日志，在最近 20 页样本内筛出 9 条图片透传预扣：Nano 1 条、GPT VIP 8 条；每条日志的 `delta_usd` 为 +0.027397。样本内仅见 GPT VIP 1 条对应类型的退款，`delta_usd` 为 -0.027397。预扣记录的 request ID 是透传代码生成的 `video_<epoch>_<random>`，无法与无标识截图唯一关联。样本范围之外的日志未核对；没有同类退款记录也不能单独证明截图交易最终净损失。

标准 New API 图片通道另有一条 GPT VIP 成功消费，路径为 `/v1/images/edits`，以及多条 quota=0 的 400 错误。没有证据证明该成功记录与截图有关。管理日志不保存这次生成的图片 URL；本次未找回截图对应的任务编号或图片结果。

因此，当前结论是：截图显示预扣记录，尚不能确认截图对应任务是否生成成功、是否交付丢失或用户实际净扣款。未执行人工退款。

## 已确认的源码问题

1. 旧图片透传代码在提交上游前直接调整用户与令牌额度并写消费类型预扣日志，但没有持久化图片任务或结果 URL。
2. 客户端断开后，后台轮询仍可能成功；旧代码直接返回 URL，不检查最终客户端收图情况，后续也没有查回原结果的公共入口。这是一条可行的“生成成功但未拿到图”路径，不是截图交易的现场证明。
3. 旧轮询到单轮期限后可能再提交新任务，即使旧任务仍在运行，带来重复上游生成。
4. 标准图片通道存在 HTTP 200 空结果以及流式错误被当成成功的结算风险。修复需让业务失败进入已有退款流程，同时保留有效图片的正常计费。
5. 上传 503 的生产文件系统原因尚未验证。无效密钥的 401、静态图片可读取，均不能证明上传目录可写。

## 本次代码修复的核对原则

- 本地 multipart 图片转换为受支持的参考图输入，并保留提示词审核。
- Nano 原生分辨率使用 `imageSize`，GPT 使用型号对应的像素或比例参数；不以超分替代原生 4K。
- 提交前建立持久任务，收到上游编号后持久记录，轮询始终查询同一任务；提交结果不明时不自动再次生成。
- 预留、释放、结算使用同一钱包数据库的事务并保持幂等；任务与最终消费日志能通过任务编号关联。
- 同步等待到期返回可继续查询的任务。保存已生成结果，使用 task ID 或相同 Idempotency-Key 重放，不重复生成或结算。
- HTTP 响应的 finish 仅证明交给直接下游，通常是审核代理，不能宣称终端客户已经收到图片。
- 历史预扣记录没有新账本关联，不自动迁移退款；需定位实际任务与净余额变化后处理。

## 验证边界

代码与本地模拟测试不能证明生产上传已恢复，也不能保证各型号的真实输出或找回旧请求图片。最终交付记录应分别注明本地测试、未部署状态、未做付费验收和历史交易关联限制。

## 已完成的本地修复与回归

- 八个原生图片型号采用明确的参数校验；参考图支持 URL、data URL、有效图片原始 base64，以及 multipart 本地文件；保留 Nano imageSize 的原生 4K 请求。
- 图片任务、上游任务编号与结果保存在钱包 SQLite；超时返回 task ID，查询 `/v1/images/tasks/{task_id}` 或相同 Idempotency-Key 重放可取回原结果。重放不创建新生成，也不重复结算。
- 明确生成失败、内容拒绝、无有效结果会释放预留；轮询 503 继续查询同一任务；提交结果不明进入 submit_unknown，不自动再次 POST。
- 预留、释放、结算及消费日志使用事务；数据库暂不可用时保留交付 ACK，恢复后仅结算一次。已有成功结果在过期释放预留后仍保留，取回时检查余额并重新预留。
- 标准 New API 图片响应中的 200 错误对象、空图片结果及失败/取消 SSE 不再当成正常成功。已产生有效图片后客户端断连保留正常计费。
- 上传鉴权失败与存储异常返回明确错误；本地上传及公开读回通过，生产目录、挂载、权限、空间和静态路由仍需现场证据。
