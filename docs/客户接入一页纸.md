## 2. 文本对话

`POST https://www.keyoapi.xyz/v1/chat/completions`

## 3. 图片生成与本地图编辑

文生图：`POST https://www.keyoapi.xyz/v1/images/generations`（JSON）。下表七个已文档化型号都支持文生图与参考图生成，尺寸参数按型号选择。当前 2.5 系列为 `gpt-image-2.5-flare` / `gpt-image-2.5-sunburst`；在 `/pricing` 核对完整型号及可用分组，API Key 所选分组须有该型号的可用渠道，不要自行改型号后缀。

```bash
curl https://www.keyoapi.xyz/v1/images/generations \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Idempotency-Key: circle-001" \
  -H "Content-Type: application/json" \
  -d '{"model":"nano-banana-2","prompt":"a red circle on white background","aspectRatio":"1:1","imageSize":"2K","n":1,"response_format":"url","replyType":"async"}'
```

| model | 尺寸字段 | quality | background | mask |
|-------|----------|---------|------------|------|
| `gpt-image-2` | `size`：比例或表内 1K 像素 | `auto` | 不支持 | HTTP(S) URL |
| `gpt-image-2-vip` | `size`：约束内 1K–4K 像素或 `auto` | `medium` | `transparent` | HTTP(S) URL |
| `gpt-image-2.5-flare` | `size`：表内 1K/2K/4K 像素或 `auto` | `low` / `medium` / `high` | `transparent` | HTTP(S) URL |
| `gpt-image-2.5-sunburst` | `size`：表内 1K/2K/4K 像素或 `auto` | `low` / `medium` / `high` / `xhigh` / `max` | `transparent` | HTTP(S) URL |
| `nano-banana-2` | `aspectRatio` + `imageSize`：`1K` / `2K` / `4K` | 不支持 | 不支持 | 不支持 |
| `nano-banana-2.1` | `aspectRatio` + `imageSize`：`1K` / `2K` / `4K` | 不支持 | 不支持 | 不支持 |
| `nano-banana-pro` | `aspectRatio` + `imageSize`：`1K` / `2K` / `4K` | 不支持 | 不支持 | 不支持 |

Nano 用原生 `aspectRatio` + `imageSize`，不要填 GPT 像素尺寸。公共比例：`auto` / `1:1` / `16:9` / `9:16` / `4:3` / `3:4` / `3:2` / `2:3` / `5:4` / `4:5` / `21:9`；2 / 2.1 另支持 `1:4` / `4:1` / `1:8` / `8:1`，Pro 不支持这四种。`gpt-image-2` 基础版只到 1K；VIP / flare / sunburst 用像素或 `auto`，常用 16:9 为 `1280x720` / `2048x1152` / `3840x2160`，1:1 为 `1024x1024` / `2048x2048` / `2880x2880`。VIP 自定义尺寸须最长边 ≤ 3840、边长为 16 的倍数、比例 ≤ 3:1、总像素 655,360–8,294,400；flare / sunburst 只接受表内尺寸。完整表见 [AI 手册 §3.1](https://www.keyoapi.xyz/brand/keyo-api-ref.md)。

**参考图：** JSON 加 `"images":["https://example.com/reference.png"]`，也支持图片 data URL 和有效图片的原始 base64（别名 `image_urls` / `image_url` / `image`）。不要把本机路径写进 JSON；本地图可直接 multipart 上传，无须先换 URL：

**上传限制：** 直接上传 / 内联 base64 单张原始或解码后图片 ≤ **20 MiB**；整个 multipart 请求 ≤ **32 MiB**；图片转换为 base64 后的完整 JSON 请求也须 ≤ **32 MiB**（1 MiB = 1,048,576 字节）。base64 约膨胀为原始数据的 **4/3**，多图不能按每张 20 MiB 简单相加；原图合计应小于约 24 MiB，还须为提示词和其它参数留空间。multipart 图片必须是带 `filename` 的文件 part（如下面的 `-F image=@...`）；普通文本 part 上限 **64 KiB**，不要用 `-F image=大段base64`，已有 base64 请放 JSON `images`。multipart 文件 / 请求体或完整 JSON 请求体超限返回 **413**，不会创建生成任务；缩小请求或改用可访问的图片 URL 后再提交。

**4K 输入不等于 4K 输出：** 参考图按上述字节限制上传；输出 `size` / `imageSize` 仍按型号能力选择，GPT 基础型号只支持其列出的 1K 输出尺寸。

```bash
curl https://www.keyoapi.xyz/v1/images/edits \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Idempotency-Key: local-edit-001" \
  -F model=nano-banana-2 \
  -F 'prompt=保持人物身份，改为水彩画风' \
  -F image=@./reference.png \
  -F aspectRatio=16:9 \
  -F imageSize=2K \
  -F n=1 \
  -F response_format=url \
  -F replyType=async
```

只支持 `n=1`、`response_format=url`。`stream=true`、`b64_json` 输出模式、base64/binary mask（如 `-F mask=@...`）未支持；GPT `mask` 只接受 HTTP(S) URL，Nano 不支持 `mask`。

**取回图片：** `replyType:"async"` 在任务尚未完成时返回 HTTP 202 和 `task_id`；已有终态（如幂等重放）可直接返回 200（成功）或 502（任务失败 / 提交结果不确定）。用同一把 Key 查询 `GET /v1/images/tasks/{task_id}`。`replyType:"json"`（默认）等待结果，等待超时且任务尚未完成时返回同一任务的 202，任务继续；不要新建生成来重试。GET 进行中返回 202（`reserved` / `submitting` / `running`）；完成返回 HTTP 200，`status:"succeeded"` 与非空 `data[].url`（其它异步能力的成功状态按各接口判断）。已记录的任务终态错误返回 502，含 `error.code` 和 `error.task_id`；`image_submission_unknown` 时保留 ID 联系支持，不重新生成。临时查询错误 `image_task_unavailable` 返回 502，可仅含 `request_id` 而无 `task_id`，不代表任务失败：用已保存的同一任务 ID 重试 GET。提交转发错误 `image_forwarding_failed` 也可能无 `task_id`；有 ID 就查询原任务，无 ID 就用原幂等键和参数重放。参数、鉴权、余额或服务不可用等错误按实际 HTTP 状态和 `error.code` 处理，不能一律视为任务终态失败。

```bash
curl https://www.keyoapi.xyz/v1/images/tasks/img_00000000-0000-4000-8000-000000000001 \
  -H "Authorization: Bearer sk-你的密钥"
```

**避免重复生成和扣费：** `Idempotency-Key` 为 1–128 个可见 ASCII 字符；同一把 Key、同一幂等键和相同生成参数重放取回原任务/结果，不新生成，参数冲突返回 409。连接中断未拿到任务 ID 时，用原幂等键和参数重放；有意新建图片才使用新的幂等键。

每张按次计费，实时单价见 [/pricing](https://www.keyoapi.xyz/pricing)。提交预留额度，交付结果响应时结算一次；失败或缺少有效图片时不结算并释放预留。预留默认 600 秒到期释放，仍保留任务/结果，后续取回未结算结果需足够余额。成功响应 `billing.charged:false` 可能是结算前快照，不代表免费；已结算结果的 GET/幂等重放不再次收费。历史账单争议需携带 `task_id` 联系支持。

**媒体硬规则（所有模型）：**

- 请求体必须是 **JSON**（不要对生成口 multipart 传本地文件）

- 本机文件：先 `POST /v1/uploads`（别名 `/v1/files`）拿返回的 `url`，再写进 JSON；**没有** `POST /v1/assets` / `asset://`
- 轮询：`GET /v1/tasks/{task_id}`（复数 tasks，不是 TTS 的 `/v1/task/`）

#### 4.2.1 通用：文生视频（示例）

```bash
curl https://www.keyoapi.xyz/v1/videos/generations \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d "{

#### 4.2.2 `wan3.0-video`（模式由字段推断）

| 模式 | 怎么写 |
|------|--------|
| 文生 | 仅 `prompt` + `resolution` + `duration`（`2`–`30` 或 `-1`）+ 可选 `size`/`aspect_ratio` |

| 文件/网页 | `file_url` **或** `link_url`（二选一；可无 prompt） |

    {"url": "https://example.com/last.jpg", "role": "last_frame"}

```

#### 4.2.5 `MiniMax-H3`

**本模型字段与 Seedance/Wan 不同。** 只用 `images[]` / `audios[]`。传 `first_frame_image` / `image_with_roles` 会直接 400。

| 字段 | 说明 |
|------|------|
| `model` | 固定 `MiniMax-H3` |
| `prompt` | 必填 |
| `aspectRatio` | **必填**：`landscape` / `portrait`（可用 `16:9` / `9:16` 别名；不支持 `square` / `1:1`） |
| `resolution` | 无参考图：`768p` / `2k`；有参考图：`480p` / `720p` / `768p` / `1080p` / `2k`。不要把画幅写进 resolution |
| `duration` | 无参考图：整数 **4–15** 秒；有参考图：整数 **1–15** 秒 |
| `images` | 可选，参考图，最多 9；公网 https |
| `audios` | 可选，参考音频，最多 3；公网 https |
| `videos` | 仅无图模式可用作视频参考，公网 HTTP(S) URL |
| `seed` | 仅有参考图时可用，须为整数；无图请求不要传 |

兼容别名：`image_urls`→`images`，`audio_urls`→`audios`，`aspect_ratio`→`aspectRatio`。

仅音频 / 视频参考仍属**无参考图**模式，分辨率与时长限制不变；省略分辨率 / 时长默认 `768p` / 5 秒。无图请求的 `480p` / `720p` / `1080p`、1–3 秒、非整数时长或 `seed` 会返回 HTTP 400，应改参数后再提交。

**文生：**

```json
{
  "model": "MiniMax-H3",
  "prompt": "一只红气球在蓝天缓缓上升，电影感，自然光",
  "aspectRatio": "landscape",
  "resolution": "768p",
  "duration": 5
}
```

**参考图 + 参考音频：**

```json
{
  "model": "MiniMax-H3",
  "prompt": "人物按参考音色说话，镜头缓慢推进",
  "aspectRatio": "portrait",
  "resolution": "768p",
  "duration": 8,
  "images": ["https://example.com/char.png"],
  "audios": ["https://example.com/voice.mp3"]
}
```

> 提交仍走 `POST /v1/videos/generations`，轮询 `GET /v1/tasks/{task_id}`（与其它视频模型同一套 Keyo 路径）。

#### 4.2.6 `gemini-omni-1.1-flash`

| 模式 | 怎么写 |
|------|--------|
| 文生 | `prompt` + `resolution`(`360p`/`720p`/`1080p`/`4k`) + `aspect_ratio`；**无 `duration`** |
| 多主体参考 | `image_urls` 多张 + prompt 说明关系 |
| 首尾帧 | `first_frame_image` + `last_frame_image`，或 `image_with_roles` |
| 视频编辑/延长 | `video_urls`（≤1 段，≤10s）或 `extend_from_task_id` |

```json
{
  "model": "gemini-omni-1.1-flash",
  "prompt": "smooth transition, camera slowly pushes in",
  "first_frame_image": "https://example.com/start.jpg",
  "last_frame_image": "https://example.com/end.jpg",
  "resolution": "720p"
}
```

#### 4.2.6b `gemini-omni-1.1-flash-ext`

| 规则 | 说明 |
|------|------|
| `duration` | **仅** `4` / `6` / `8` / `10` |
| `image_urls` | **0 / 1 / 3** 张（**不要传 2 张**） |
| `generation_type` | `frame`（必须恰好 1 图）或 `reference`（1 或 3 图） |
| `video_urls` | 0 或 1；**有视频时不要传 duration** |

## 6. 语音合成（TTS）

### 6.1 同步（立刻返回音频）

`POST https://www.keyoapi.xyz/v1/audio/speech`

```bash
curl https://www.keyoapi.xyz/v1/audio/speech \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d "{
    \"model\": \"GLM-TTS\",
    \"input\": \"你好，我是 KeyoAPI。\",

  }" \
  --output speech.wav
```

适合：`GLM-TTS`、`Step-Audio-TTS-3B`、部分 `IndexTTS-2` 场景。

### 6.2 异步（先拿任务 ID，再轮询结果）

`POST https://www.keyoapi.xyz/v1/async/audio/speech`  
然后：`GET https://www.keyoapi.xyz/v1/task/{任务ID}`

```bash
# 创建任务
curl https://www.keyoapi.xyz/v1/async/audio/speech \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d "{\"model\":\"Qwen3-TTS\",\"inputs\":\"你好，异步语音合成。\"}"

# 用返回的 task id 查结果
curl https://www.keyoapi.xyz/v1/task/任务ID \
  -H "Authorization: Bearer sk-你的密钥"
```

适合：`Qwen3-TTS`、`CosyVoice3`，以及需要异步的 `IndexTTS-2`。

## 7. 扩展能力（非 Cursor / ChatBox 一键场景）

这些模型在 [/pricing](https://www.keyoapi.xyz/pricing) 可见，但**不是**标准「只填 Base URL」就能在聊天客户端里用完的；需要按路径用 HTTP / SDK 调用。

| 能力 | 路径 | 模型 |
|------|------|------|
| OCR / 文档理解（chat） | `POST /v1/chat/completions` | Unlimited-OCR |
| 文档解析（异步） | `POST /v1/async/documents/parse` → `GET /v1/task/{id}` | MinerU2.5-Pro |
| 抠图 | `POST /v1/images/mattings` | RMBG-2.0 |
| 超分 | `POST /v1/images/upscaling` | Real-ESRGAN、AnimeSharp |
| 文档展平 | `POST /v1/images/unwarping` | UVDoc |
| 目标检测 | `POST /v1/images/object-detection` | VajraV1、sam3 |
| 图像分割 | `POST /v1/images/segmentation` | VajraV1、sam3 |
| 人体关键点 | `POST /v1/images/pose-detection` | VajraV1 |
| 数字人（音视频→视频，异步） | `POST /v1/async/videos/audio-video-to-video` → `GET /v1/task/{id}` | Duix-Avatar（multipart `ref_audio` + `ref_video`，最长 60 秒） |
| 说话视频（图→视频，异步） | `POST /v1/async/videos/image-to-video` → `GET /v1/task/{id}` | InfiniteTalk |

InfiniteTalk 使用 multipart 必填字段 `model=InfiniteTalk`、`prompt`、`cond_video`（可直接传人物图片）和 `cond_audio`。**单任务音频最长 15 秒**。分辨率 480P / 720P。没有拿到任务 `id` 时，不要盲目重复提交。

Duix-Avatar 使用 multipart 必填字段 `model=Duix-Avatar`、`ref_audio`、`ref_video`（必须是文件，不能只传 URL）。**音频最长 60 秒**。按分辨率×时长分档按秒计费（见 /pricing 分组价格）。
| 系统一决策（Jev / Open-Jev） | `POST /v1/systemone` | `jev-1.13.0`（~$0.0336 / $0）、Bespoke-Nimble-9B（~$0.032 / $0） |
| 内容风控 | `POST /v1/moderations` | nonescape-v0、keyo-text-moderation、Security-semantic-filtering、nsfw-classifier |
| 向量 | `POST /v1/embeddings` | WeMM-Embedding-9B、WeMM-Embedding-4B、WeMM-Embedding-2B、Qwen3-VL-Embedding-8B |
