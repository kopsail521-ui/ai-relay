# 接入文档静态审计

审计范围：公开接入文档、视频请求契约、特殊能力透传路由。未调用任何模型，也未发送真实生成请求。

## 已确认的文档错误

### 0. Seedance 查询路径需要按能力族区分

Seedance 等 Path B 视频任务的规范查询路径是 `GET /v1/tasks/{id}`；`GET /v1/videos/{id}` 是 Path A 视频的查询路径。视频网关目前同时识别两种路径，主入口也会在任务不存在时尝试兼容转发，因此不需要额外暴露供应商路径。公开文档已把 Seedance 固定写成 `/v1/tasks/{id}`，避免 AI 工具选错路径。

### 1. MiniMax-H3 曾错误宣称支持 `square` / `1:1`

网关会在提交前明确拒绝这两个值，返回 `aspectRatio` 参数错误；可用值只有 `landscape`、`portrait`，以及 `16:9`、`9:16` 别名。客户文档和网页字段表已改正。

### 2. `grok-1.5-video` 的时长不是任意 1–15 秒

当前契约只接受 `seconds=6` 或 `seconds=10`。文档中的 1–15 秒描述会让用户构造出必然 400 的请求。中文网页说明已改为“仅 6 秒或 10 秒”，一页纸原文已经写明该限制。

### 3. 视频和其他异步能力使用不同的轮询路径

- 视频生成：`GET /v1/tasks/{id}`（`tasks`，复数）
- 异步 TTS、文档解析、InfiniteTalk：`GET /v1/task/{id}`（`task`，单数）

这不是排版差异，路径写错会得到 404。公开文档现在把两类路径分开说明。

### 4. 异步 TTS 的正文键名是 `inputs`

异步语音接口使用 `POST /v1/async/audio/speech`，正文需要 `model` + `inputs`。网关同时把常见的 `input` 别名转换为 `inputs`，因此旧示例仍能兼容；同步语音接口仍使用 `input`。中文、英文和网页示例已分别改成正确键名。

### 5. 已覆盖的模型能力族

静态检查覆盖了对话、图片、Path A/Path B 视频、ASR、同步/异步 TTS、OCR、文档解析、抠图、超分、检测、分割、姿态、InfiniteTalk、内容审核、向量和重排。除明确下架的数字人模型外，公开手册的模型名与当前目录逐项核对，`GET /v1/models` 仍是运行时可用性的最终校验入口。

### 6. InfiniteTalk 的字段与时长合同

公开示例原先写成 `image` + `audio`，但用户提供的 400 错误显示当前接口要求 `cond_video` + `cond_audio` 和 `prompt`；公开手册已改为这些字段，网关同时兼容旧别名。上游 InfiniteTalk 为无限时长（时长跟随音频）；Keyo **不再**在网关侧强制 15 秒上限，长音频应整段一次提交，不要擅自切成多段按次计费。分辨率上游为 480P / 720P。InfiniteTalk 轮询仍是单数 `GET /v1/task/{id}`。

网关对明确的 HTTP 错误退回预扣额度；提交超时但没有任务号时，任务是否创建仍未知，不能据此推断已退款或未计费。调用方应保留请求时间并联系支持核查，禁止盲目重试，否则可能重复计费或创建重复任务。

## 当前实现中容易被误用、但不属于文档 bug 的规则

- 视频生成体必须是 JSON；媒体字段必须是可公网访问的 `http(s)` URL。`data:`、本机路径、`asset://` 会在扣费前拒绝。
- 本机媒体先用 `POST /v1/uploads`（别名 `/v1/files`）上传，表单字段使用 `file`；返回 JSON 中的 `url` 才能填入视频请求。上传接口支持的文件包括常见图片、音频、视频和 PDF，单文件上限由部署配置决定。
- Seedance 的 `first_frame_image` / 首尾帧模式不能和参考音频、参考视频混用；参考音视频必须使用 `image_urls` / `images` 等参考模式，并至少提供一张图片或一段视频。
- `gemini-omni-1.1-flash` 不接受 `duration`；`gemini-omni-1.1-flash-ext` 的图片数量只能是 0、1、3，且带参考视频时不要同时提交 `duration`。
- `MiniMax-H3` 使用 `images[]`、`audios[]`，不能套用 Seedance/Wan 的 `first_frame_image` 或 `image_with_roles` 字段。

## 建议的排错顺序

1. 先用 `GET /v1/models` 核对模型名是否完全一致。
2. 确认请求路径与模型类型匹配，并确认轮询路径的单复数。
3. 对视频请求检查 `Content-Type: application/json`、媒体 URL 可公网访问、模型专属字段和时长范围。
4. 再检查 API Key、余额和上游临时状态。
