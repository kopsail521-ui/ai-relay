Overview

CosyVoice3 is an asynchronous text-to-speech option on KeyoAPI. Submit text with your existing API key, save the returned task identifier, and retrieve the finished audio when processing completes. It shares the account wallet with speech recognition, chat and avatar tasks, but each capability has its own request fields and result rules.

POST /v1/async/audio/speech with model=CosyVoice3 and a string inputs containing the target text. Both prompt_wav_url and prompt_text are required. The reference must be a downloadable WAV or MP3, at most 30 seconds, sampled at least at 16 kHz. Replace the example URL with a real file that the server can download without signing in, and replace prompt_text with the exact reference transcript. Text alone is not a complete request. Unlike Qwen3-TTS, this model does not use an inputs array.

After submission, save id or task_id before doing other work. Query GET /v1/task/{id} with the same API key while status is processing. On completed, inspect the actual output. Download from url or output.file_url only if present. For batch requests, process each returned item rather than assuming one audio URL. Keep the complete response for support if the output shape is unexpected; do not automatically submit a replacement. Stop on failed or cancelled and preserve the error and request identifier for support. Do not use the plural video query path /v1/tasks/{id} for this endpoint.

Optional instruct_text describes delivery, speed ranges from one to five, and seed is optional. These fields do not guarantee emotion, accent, gender or a particular voice quality. Do not substitute OpenAI voice names for the required reference fields. The URL-based request does not define an enrollment service or reusable voice-ID lifecycle; confirm those separate workflows with support before designing them. Keep each model’s fields separate rather than changing only its name in another TTS example.

For application integration, store the task ID with your own request record. A temporary query failure can be retried with that same ID. A submission timeout is ambiguous and should not trigger an automatic replacement speech task: the original may already be processing. Keep API keys on the server and record errors without authorization headers or raw private media.

Where it fits

Speech models on KeyoAPI split into transcription (audio in, text out via multipart upload) and synthesis (text in, audio out, some via async task polling). Both directions bill on the same prepaid wallet as chat, so voice features can ride an existing balance without a second vendor account. For pipelines, transcription feeds agents and logs; synthesis closes the loop for voice replies.

Limits and good-fit use

Audio format and duration limits follow the endpoint contract: sync speech returns audio bytes directly, while async speech submits a task and returns a pollable id. Always verify live rates on the pricing list — speech models meter per request, per second or per 10k characters depending on the model.

Request contract

Speech requests split by direction. Transcription uploads audio as multipart form data with the model field, returning JSON text; synthesis posts JSON (or multipart for some clones) and returns audio bytes synchronously, or a task id for async lanes that you poll on the task endpoint until the render completes. Both directions authenticate with the same Bearer key as chat, and both deduct from the same prepaid wallet at the per-request or per-character rate listed above.

FAQ

How do I call the CosyVoice3 API?

POST /v1/async/audio/speech with model=CosyVoice3, a string inputs, required prompt_wav_url and exact prompt_text. Use a downloadable WAV/MP3 reference of at most 30 seconds and at least 16 kHz; save id/task_id and poll GET /v1/task/{id}.

Is CosyVoice3 synchronous?

No. On KeyoAPI it uses POST /v1/async/audio/speech — create a task, then poll GET /v1/task/{id}. For a sync round trip, use IndexTTS-2 on /v1/audio/speech.

What is CosyVoice3 good for?

Reference-based speech with optional instruct_text and speed controls. These controls guide delivery without guaranteeing emotion, gender or voice quality.
