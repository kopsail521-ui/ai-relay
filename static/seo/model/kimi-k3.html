Quick start

Base URL: https://www.keyoapi.xyz/v1

Endpoint: POST /v1/chat/completions

Model: model=kimi-k3

cURL (Streaming Chat Completion)

curl https://www.keyoapi.xyz/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [
      {"role": "system", "content": "You are an expert programming assistant."},
      {"role": "user", "content": "Explain how to handle backpressure in streaming LLM pipelines."}
    ],
    "stream": true,
    "max_tokens": 1024
  }'

Python (openai>=1.0 SDK)

import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ.get("KEYO_API_KEY", "YOUR_API_KEY"),
    base_url="https://www.keyoapi.xyz/v1",
)

response = client.chat.completions.create(
    model="kimi-k3",
    messages=[
        {"role": "system", "content": "You are a code analysis agent."},
        {"role": "user", "content": "Analyze repository architecture and identify bottlenecks."},
    ],
    temperature=0.6,
    max_tokens=1500,
    stream=True,
)

for chunk in response:
    content = chunk.choices[0].delta.content or ""
    print(content, end="", flush=True)

Node.js (openai NPM Package)

import OpenAI from "openai";

const openai = new OpenAI({
  apiKey: process.env.KEYO_API_KEY || "YOUR_API_KEY",
  baseURL: "https://www.keyoapi.xyz/v1",
});

async function main() {
  const stream = await openai.chat.completions.create({
    model: "kimi-k3",
    messages: [
      { role: "system", content: "You are an automated support classifier." },
      { role: "user", content: "Categorize ticket #8492 and draft an initial resolution response." },
    ],
    stream: true,
  });

  for await (const chunk of stream) {
    process.stdout.write(chunk.choices[0]?.delta?.content || "");
  }
}

main().catch(console.error);

Auth uses the same Bearer API key as chat. Full notes: Keyo docs.

FAQ

How do I call kimi-k3 on KeyoAPI?

Point any standard OpenAI SDK or HTTP client base URL to https://www.keyoapi.xyz/v1, set Authorization: Bearer YOUR_API_KEY, and provide model=kimi-k3 in your POST /v1/chat/completions payload. No specialized SDK or adapter is required.

Is there a free path for Kimi K3 API key prototyping?

Yes. Every new account registered at the sign-up page receives a one-time $10 welcome balance. For risk-free testing without drawing down paid credits, use gift-credit model IDs on the gift-credit models page. Once your schemas and logic are verified, switch model= to kimi-k3 on the exact same API key and base URL.

What context window does kimi-k3 support?

kimi-k3 features an ultra-large 256K token context window (approximately 200,000 English words or 400,000 Chinese characters). This enables feeding entire code repositories, financial filings, and long conversational histories directly in prompt context.

Is the model ID kimi-k3 case-sensitive?

Yes. The exact API model string must be kimi-k3 in lowercase. Calling Kimi-K3, KIMI-K3, or moonshot-k3 will fail validation and return a model_not_found error from the gateway.

Who is the upstream vendor behind Kimi K3?

Kimi K3 is developed by Moonshot AI (北京月之暗面科技有限公司), a prominent frontier AI lab specializing in ultra-long context reasoning architectures, complex mathematical deduction, and agentic reinforcement learning.

Does kimi-k3 support streaming and function calling?

Yes. Server-Sent Events (SSE) streaming via stream=true is fully supported for real-time token delivery. OpenAI-compatible tools and function calling parameters are also recognized for building agent workflows.

How does kimi-k3 compare to deepseek-v4.1-flash for agent loops?

deepseek-v4.1-flash is a lower-cost model (~$0.14 / $0.56 per 1M) with a 128K context window, best optimized for rapid intent classification and message triage. kimi-k3 (~$0.20 / $1.02 per 1M) offers twice the context window (256K) and superior SWE-bench verified coding capabilities (79.0%), making it the superior choice for primary code execution and long-document reasoning.

What error codes should I handle and what is the recommended retry policy?

Monitor for HTTP 429 (rate limits) and HTTP 504 / 502 (upstream vendor timeout during peak traffic). Implement exponential backoff with jitter (starting at 2s). For mission-critical endpoints requiring strict sub-5s response guarantees, configure client-side fallback to deepseek-v4.1-flash or glm-5.3 on the same Keyo key.
